01

概述与设计哲学

MobX 的核心思想来自 TFRP（透明函数式响应式编程）——你只需描述数据之间的关系，框架自动追踪依赖并最小化更新。

02

Observable — 响应式状态

observable 将普通值/对象/数组包装为可被追踪的响应式结构。当这些值被 Reaction 或 Computed 读取时，MobX 自动建立订阅关系。

基础用法

import { makeObservable, observable, action, computed } from 'mobx';

class TodoStore {
  todos = [];
  filter = 'all';

  constructor() {
    makeObservable(this, {
      todos:          observable,    // 追踪数组的增删改
      filter:         observable,    // 追踪字符串变化
      filteredTodos:  computed,      // 派生，自动缓存
      addTodo:        action,        // 批量事务更新
    });
  }

  get filteredTodos() {
    return this.todos.filter(t => t.status === this.filter);
  }

  addTodo(text) {
    this.todos.push({ text, status: 'active' });
  }
}
import { makeAutoObservable } from 'mobx';

class CounterStore {
  count = 0;

  constructor() {
    // 自动推断：普通属性 → observable
    //          getter    → computed
    //          方法      → action
    makeAutoObservable(this);
  }

  get doubled() {
    return this.count * 2;  // 自动成为 computed
  }

  increment() {
    this.count++;           // 自动成为 action
  }
}

内部实现：Proxy + ObservableAdministration

observable-impl.js
JS
// 简化版核心实现
class ObservableValue {
  constructor(value) {
    this._value = value;
    this._observers = new Set();  // 订阅该值的 Derivation 集合
  }

  get() {
    // 关键！将当前 globalTrackingDerivation 加入订阅者
    if (globalTrackingDerivation) {
      this._observers.add(globalTrackingDerivation);
      globalTrackingDerivation.newObserveds.add(this);
    }
    return this._value;
  }

  set(newValue) {
    if (newValue === this._value) return;
    this._value = newValue;
    // 通知所有 observers 重新计算
    this._observers.forEach(obs => obs.invalidate());
  }
}

// globalTrackingDerivation 是 MobX 全局追踪上下文
// 在 autorun/computed 运行函数时设置，运行结束后清除
let globalTrackingDerivation = null;

function trackDerivedFunction(derivation, fn) {
  const prev = globalTrackingDerivation;
  globalTrackingDerivation = derivation;
  derivation.newObserveds = new Set();
  try {
    return fn();   // fn 执行期间所有 get() 都会注册依赖
  } finally {
    globalTrackingDerivation = prev;
    // 对比新旧依赖，清理失效的订阅
    diffAndUpdateDependencies(derivation);
  }
}
💡
MobX 在现代版本（v6+）中使用 ES6 Proxy 拦截属性访问，旧版（v4/v5）通过 Object.defineProperty getter/setter 实现，Proxy 的优势在于可追踪新增属性和数组索引访问。
03

Computed — 派生值与缓存

Computed 是 MobX 的精华之一：它是一个 惰性求值 + 结果缓存 的派生值，只有当依赖变化且有订阅者时才重新计算。

Computed 生命周期
1
创建 — POSSIBLY_STALE

computed 首次创建时标记为 "可能过期"，还未执行计算函数。

state: POSSIBLY_STALE | NOT_TRACKING
2
首次读取 — 求值并追踪依赖

调用 .get() 触发 trackDerivedFunction，收集依赖，缓存结果。状态置为 UP_TO_DATE。

computed.get() → trackDerivedFunction(fn) → cache result
3
依赖变更 — 置为 STALE

上游 observable 改变，向下广播 STALE 信号给所有依赖该 computed 的 Reaction。

observable.set() → propagate STALE to observers
4
再次读取 — 检查是否真正过期

MobX 先检查直接依赖是否真的变了（节省计算），若无变化则复用缓存（钻石依赖优化）。

if (dependenciesUnchanged) return cachedValue;
5
无订阅者 — 挂起追踪

computed 没有 Reaction 消费时，自动停止对上游的订阅，避免内存泄漏。

if (observers.empty) state = NOT_TRACKING;

Computed 实现骨架

computed-impl.js
JS
class ComputedValue {
  constructor(derivation) {
    this._derivation = derivation;   // 计算函数
    this._value      = undefined;
    this._state      = 'NOT_TRACKING';
    this._observers  = new Set();
    this._observeds  = new Set();    // 订阅的上游 observable
  }

  get() {
    // 将自身注册到上层的追踪上下文
    if (globalTrackingDerivation) {
      this._observers.add(globalTrackingDerivation);
    }
    // 按需重新计算
    if (this._state !== 'UP_TO_DATE') {
      this._computeValue();
    }
    return this._value;
  }

  _computeValue() {
    const newValue = trackDerivedFunction(this, this._derivation);
    const changed  = !isEqual(newValue, this._value);  // 支持自定义 equals
    this._value = newValue;
    this._state = 'UP_TO_DATE';
    if (changed) this._notifyObservers();  // 值真正变了才向下传播
  }

  invalidate() {
    if (this._state === 'UP_TO_DATE') {
      this._state = 'STALE';
      this._observers.forEach(obs => obs.invalidate());  // 向下广播
    }
  }
}
🚀
钻石依赖优化：当多个 computed 依赖同一 observable 时（形成钻石形依赖图），MobX 通过两阶段传播（标记 STALE → 延迟求值）确保每个 computed 只计算一次，不会出现重复计算或中间状态闪烁。

Action — 事务性变更

Action 将多个 observable 变更包裹在一个 事务（transaction） 中，确保中间状态不触发 Reaction，批量通知依赖。

Action API

action-demo.js
JS
import { action, runInAction, flow } from 'mobx';

// ① 装饰器 / 包裹函数
const setUser = action('setUser', (store, user) => {
  store.name  = user.name;   // 事务内：不触发 Reaction
  store.age   = user.age;
  store.email = user.email;
  // 事务结束：批量通知一次
});

// ② runInAction：临时创建匿名 action（常用于 async 回调）
async function fetchUser(id) {
  const data = await api.get(id);
  runInAction(() => {
    store.user   = data;
    store.loaded = true;
  });
}

// ③ flow：generator 版本，自动处理异步的 runInAction
const loadData = flow(function*() {
  store.loading = true;
  const data = yield fetch('/api/data');
  store.data    = yield data.json();   // yield 自动 runInAction
  store.loading = false;
});

Transaction 实现原理

transaction-impl.js
JS
let batchDepth = 0;
const pendingReactions = [];

function startBatch() {
  batchDepth++;
}

function endBatch() {
  if (--batchDepth === 0) {
    // 批次结束，统一执行所有 pending reactions
    while (pendingReactions.length) {
      pendingReactions.shift().runReaction();
    }
  }
}

function action(fn) {
  return function(...args) {
    startBatch();
    try {
      return fn(...args);
    } finally {
      endBatch();    // 即使抛出异常也确保 batch 结束
    }
  };
}
⚠️
MobX 6 起默认开启 strict mode（通过 configure({enforceActions: 'always'})），在 action 外修改 observable 会抛出异常，强制规范变更路径。
05

Reaction — 副作用

Reaction 是 MobX 响应式图的 叶节点——它不产生值，只执行副作用（UI 更新、日志、网络请求等）。

autorun

observable → 立即执行并追踪全部依赖
任意依赖变化时重新执行

reaction

data fn → 追踪数据源（不执行副作用）
effect fn → 数据变化时执行

when

predicate → 追踪条件
effect → 条件首次为 true 时执行一次
reactions-demo.js
JS
import { autorun, reaction, when } from 'mobx';

// ① autorun：立即执行，自动追踪所有依赖
const dispose1 = autorun(() => {
  console.log(`Count: ${store.count}`);   // 读取即订阅
});
dispose1();  // 调用返回值来取消监听

// ② reaction：分离"数据追踪"和"副作用"
const dispose2 = reaction(
  () => store.count,              // data fn：返回要追踪的值
  (newVal, oldVal) => {           // effect fn：值变化时执行
    console.log(newVal, oldVal);
  },
  { fireImmediately: false }   // 默认首次不执行
);

// ③ when：条件满足时一次性触发
when(
  () => store.isLoaded,
  () => console.log('数据加载完毕！')
);

// Promise 形式
await when(() => store.isLoaded);
console.log('继续执行...');

Reaction 执行流程

reaction-impl.js
JS
class Reaction {
  constructor(name, onInvalidate) {
    this.name          = name;
    this.onInvalidate  = onInvalidate;  // 依赖失效时的回调
    this._observeds    = new Set();
    this._isScheduled  = false;
  }

  track(fn) {
    // 以自身作为追踪上下文执行 fn
    return trackDerivedFunction(this, fn);
  }

  invalidate() {
    // 由上游 observable/computed 调用
    if (!this._isScheduled) {
      this._isScheduled = true;
      scheduleReaction(this);   // 推入 pendingReactions 队列
    }
  }

  runReaction() {
    this._isScheduled = false;
    this.onInvalidate();   // 执行用户副作用
  }
}

// autorun 实现
function autorun(view) {
  const reaction = new Reaction('autorun', () => {
    reaction.track(view);    // 每次执行都重新追踪依赖
  });
  reaction.track(view);     // 首次立即执行
  return () => reaction.dispose();
}

双向边管理

dependency-graph.js
JS
// 每个 Derivation（Computed/Reaction）都持有双向边
class Derivation {
  observeds    = new Set();  // 我依赖的 observables（下游 → 上游）
  newObserveds = new Set();  // 本次追踪收集到的新依赖
}

// 每个 Observable 也持有反向边
class Observable {
  observers = new Set();  // 依赖我的 derivations（上游 → 下游）
}

// 依赖 diff：每次重新追踪后，比较新旧依赖集合
function diffAndUpdateDependencies(derivation) {
  const { observeds, newObserveds } = derivation;

  // 移除不再依赖的 observable
  observeds.forEach(obs => {
    if (!newObserveds.has(obs)) {
      obs.observers.delete(derivation);  // 断开反向边
    }
  });

  // 添加新依赖
  newObserveds.forEach(obs => {
    if (!observeds.has(obs)) {
      obs.observers.add(derivation);     // 建立反向边
    }
  });

  derivation.observeds = newObserveds;
}
🔑
关键洞察：MobX 的依赖收集是动态的、运行时的——每次 Derivation 重新执行，依赖都会重新收集。这意味着条件分支中的依赖变化（如 if(a) b.x else c.y）会被精确追踪，只订阅实际访问的路径。

集成原理概述

mobx-react 的本质是：将 React 组件的渲染函数（render）包装成一个 MobX Reaction。当组件渲染时自动追踪所有被访问的 observable；当依赖变化时，强制触发组件重渲染。

🪶

observer HOC — 核心实现

函数式组件 observer

observer-fc-impl.jsx
JSX
import { Reaction } from 'mobx';
import { useRef, useReducer, useEffect, forwardRef } from 'react';

function observer(baseComponent) {
  const WrappedComponent = forwardRef((props, ref) => {
    // ① 强制更新触发器
    const [, forceUpdate] = useReducer(x => x + 1, 0);

    // ② 每个实例持有一个 Reaction
    const reactionRef = useRef(null);
    if (!reactionRef.current) {
      reactionRef.current = new Reaction(`observer(${baseComponent.name})`, () => {
        forceUpdate();  // 依赖失效时触发 React 重渲染
      });
    }

    // ③ 组件卸载时销毁 Reaction
    useEffect(() => {
      return () => reactionRef.current.dispose();
    }, []);

    // ④ 在 Reaction.track() 内执行 render，自动收集依赖
    let renderResult;
    reactionRef.current.track(() => {
      renderResult = baseComponent(props, ref);
    });

    return renderResult;
  });

  WrappedComponent.displayName = baseComponent.name;
  return WrappedComponent;
}

// 使用示例
const Counter = observer(({ store }) => (
  <div>
    <p>{store.count}</p>   {/* 读取触发追踪 */}
    <button onClick={store.increment}>+</button>
  </div>
));

Class 组件 observer（mobx-react）

observer-class-impl.jsx
JSX
import { Component } from 'react';
import { Reaction } from 'mobx';

function makeClassComponentObserver(ComponentClass) {
  const proto = ComponentClass.prototype;
  const originalRender = proto.render;

  // 劫持 componentDidMount：创建 Reaction
  const orgDidMount = proto.componentDidMount;
  proto.componentDidMount = function() {
    this._mobxReaction = new Reaction(`observer(${ComponentClass.name})`, () => {
      this.forceUpdate();    // Class 组件用 forceUpdate
    });
    orgDidMount?.call(this);
  };

  // 劫持 componentWillUnmount：销毁 Reaction
  const orgWillUnmount = proto.componentWillUnmount;
  proto.componentWillUnmount = function() {
    this._mobxReaction.dispose();
    orgWillUnmount?.call(this);
  };

  // 劫持 render：包裹在 Reaction.track() 内
  proto.render = function() {
    let result;
    this._mobxReaction.track(() => {
      result = originalRender.call(this);
    });
    return result;
  };

  return ComponentClass;
}
💡
observer 函数组件使用 useReducer 而非 useState 来触发更新（避免触发 React 的 bail-out 优化），并将 Reaction 存在 useRef 中以确保整个组件生命周期共享同一个 Reaction 实例。

import { useRef } from 'react';
import { makeAutoObservable } from 'mobx';

function useLocalObservable(initializer, annotations) {
  // useRef 确保只在首次渲染时创建一次 observable 对象
  const storeRef = useRef(null);
  if (storeRef.current === null) {
    storeRef.current = makeAutoObservable(
      initializer(),      // 调用工厂函数
      annotations,        // 可选的 annotation overrides
      { autoBind: true }  // 自动绑定 this
    );
  }
  return storeRef.current;
}

React Concurrent Mode 兼容性

React 18 的并发模式带来了一个问题：渲染可能被中断和重试，这与 MobX Reaction 的设计存在潜在冲突。

⚠️
Tearing 问题：并发渲染中，不同优先级的渲染可能读取到不同时间点的 observable 值，导致 UI 状态撕裂（tearing）。

mobx-react-lite 的解决方案

concurrent-mode-fix.js
JS
import { useSyncExternalStore } from 'react';  // React 18 API

// mobx-react-lite v3.x 使用 useSyncExternalStore 解决 tearing
function observerFC(baseComponent) {
  return (props) => {
    const reactionRef = useRef();
    if (!reactionRef.current) {
      reactionRef.current = new Reaction('observer', notifyStore);
    }

    // useSyncExternalStore 保证快照一致性，防止 tearing
    useSyncExternalStore(
      subscribe,    // 订阅外部 store 变化
      getSnapshot,  // 获取当前快照
      getSnapshot   // 服务端快照
    );

    let renderResult;
    reactionRef.current.track(() => {
      renderResult = baseComponent(props);
    });
    return renderResult;
  };
}

// subscribe：将 React 更新回调与 MobX Reaction 连接
function subscribe(onStoreChange) {
  reactionRef.current.setScheduler(onStoreChange);
  return () => reactionRef.current.dispose();
}

shouldComponentUpdate 优化（Class 组件）

scuopt.js
JS
// Class 组件 observer 自动实现 PureComponent 效果
// 如果 forceUpdate 已触发，直接渲染（跳过 SCU）
proto.shouldComponentUpdate = function(nextProps) {
  // mobxUpdateTriggered = Reaction 触发的更新，必须渲染
  if (this._mobxUpdateTriggered) {
    this._mobxUpdateTriggered = false;
    return true;
  }
  // 否则做浅比较（如 props 改变也需要重渲染）
  return !shallowEqual(this.props, nextProps);
};

mobx-react / mobx-react-lite 完整 API

API 来源 说明
observer(component)两者将函数式组件包装为 MobX observer，渲染时自动追踪 observable 依赖
<Observer>{() => JSX}</Observer>两者将 render prop 包装为 observer，实现组件内局部响应式区域
useLocalObservable(fn, annotations?)两者创建组件本地响应式 store，相当于 useRef(makeAutoObservable(fn()))
useObserver(fn, baseComponentName?)两者低级 Hook，在 Reaction.track() 内执行 fn，手动控制追踪范围（已废弃，推荐 observer）
enableStaticRendering(true)两者SSR 模式：禁止创建 Reaction（服务端不需要响应更新），防止内存泄漏
isUsingStaticRendering()两者查询当前是否处于 SSR 静态渲染模式
useAsObservableSource(value)两者将 React props/state 暴露为可追踪的 observable（已废弃，推荐 reaction 监听 props）
Providermobx-reactContext-based store 注入（已废弃，推荐 React.createContext + useContext）
inject(...storeNames)mobx-react从 Provider 注入 stores 到 props（已废弃，推荐 useContext）
disposeOnUnmount(instance, fn[])mobx-reactClass 组件中注册 dispose 函数，在 componentWillUnmount 自动调用
componentDidMount / render 劫持mobx-react对 Class 组件使用 observer 时内部进行的生命周期劫持，用户无需感知
MobXProviderContextmobx-reactProvider 使用的 React Context 对象，可直接 useContext 替代 inject

最佳实践：推荐模式

best-practices.jsx
JSX
// ✅ 推荐：Context + useContext 替代 Provider/inject
const StoreContext = createContext(null);

function App() {
  const store = useLocalObservable(() => new RootStore());
  return <StoreContext.Provider value={store}><Router /></StoreContext.Provider>;
}

function useStore() { return useContext(StoreContext); }

const Counter = observer(() => {
  const { counter } = useStore();   // 获取 store
  return <button onClick={counter.increment}>{counter.count}</button>;
});

// ✅ 细粒度 observer：尽量让 observer 组件小而专注
// 避免：一个大的 observer 组件追踪了整个 store 树
// 推荐：将展示部分拆分为小 observer，只追踪所需字段

// ✅ SSR 正确配置
import { enableStaticRendering } from 'mobx-react-lite';
enableStaticRendering(typeof window === 'undefined');
