事件循环基础概念

JavaScript 是单线程语言，但它能通过事件循环（Event Loop）实现非阻塞的异步操作。理解事件循环，是掌握 JS 异步行为的关键。

Call Stack

调用栈

LIFO 结构，同步代码在此执行。函数调用入栈，返回出栈。

Macro Task

宏任务队列

setTimeout、setInterval、I/O、UI 事件等。每次事件循环取一个执行。

Micro Task

微任务队列

Promise.then、queueMicrotask、MutationObserver。调用栈空时全部执行。

💡
核心规则：每次取出一个宏任务执行完毕后，必须把微任务队列全部清空，才能进入下一个宏任务。微任务产生的新微任务也会被立即处理。

浏览器渲染时机

      

        浏览器在每次宏任务之间（微任务队列清空后），可能进行一次
        UI 渲染（16ms/帧），这是
        requestAnimationFrame 和
        MutationObserver 的执行节点。
      


      

        
      


      
经典代码解析


      

        

          async/await
        

        

          Promise.resolve
        

      

      

        
// async/await 底层是 Promise，await 后的代码是微任务
async function foo() {
  console.log('foo start');           // 1
  await Promise.resolve();
  console.log('foo end');             // 3（微任务）
}

console.log('script start');          // 0
foo();
console.log('script end');            // 2

// 输出: script start → foo start → script end → foo end

        

          🔍
          

            await 相当于
            Promise.then 的语法糖。await Promise.resolve()
            会将后续代码包入微任务队列，当前同步栈执行完后才执行。
          

        

      

      

        
// Promise.resolve 是已 settled 的 Promise，.then 直接入微任务队列
console.log('1');

setTimeout(() => console.log('2'), 0);

Promise.resolve().then(() => {
  console.log('3');
  setTimeout(() => console.log('4'), 0);
});

console.log('5');

// 输出: 1 → 5 → 3 → 2 → 4

        

          ⚠️
          

            微任务中产生的宏任务（setTimeout）会进入下一轮循环，在已有的
            setTimeout('2') 之后执行。

Node.js 事件循环

      

        Node.js 基于 libuv 库，事件循环比浏览器更复杂，分为 6
        个阶段，每个阶段处理特定类型的任务。
      


      

        ⚠️
        

          Node.js 独有：process.nextTick 的优先级高于
          Promise.then！二者都在阶段切换前清空，但
          nextTick 队列先于微任务队列。

process.nextTick vs Promise.then

      
// Node.js 特有优先级顺序
setTimeout(() => console.log('setTimeout'), 0);
setImmediate(() => console.log('setImmediate'));

process.nextTick(() => console.log('nextTick'));

Promise.resolve().then(() => console.log('Promise'));

// 输出（I/O 内部）: nextTick → Promise → setImmediate
// setTimeout vs setImmediate 顺序在顶层是不确定的！


      

        ✅
        

          Node.js 微任务清空顺序（每个阶段切换前）：

          process.nextTick 队列 →
          Promise 微任务队列（v11+ 后 Promise
          也可在阶段内立即执行）
        

      


      
setImmediate vs setTimeout(fn, 0)

      

        

          
setTimeout(fn, 0)

          

            进入 Timers 阶段，实际最小延迟 ~1ms，顶层调用时与 setImmediate
            顺序不确定。
          

        

        

          

            setImmediate
          

          

            进入 Check 阶段。在 I/O 回调中调用时，永远先于
            setTimeout 执行。
          

        

      

    


    


    
    

      
// Chapter 04

      
浏览器 vs Node.js 差异对比


      

        

          特性
          🌐 浏览器
          🟢 Node.js
        

        

          事件循环模型
          HTML 规范定义，浏览器实现
          libuv 实现，6 个明确阶段
        

        

          宏任务类型
          setTimeout、setInterval、I/O、UI 事件、MessageChannel
          setTimeout、setInterval、setImmediate、I/O
        

        

          微任务优先级
          Promise.then = queueMicrotask（同级）
          process.nextTick > Promise.then
        

        

          setImmediate
          ❌ 不支持
          ✅ Check 阶段执行
        

        

          process.nextTick
          ❌ 不支持
          ✅ 阶段切换前最先执行
        

        

          requestAnimationFrame
          ✅ 每帧渲染前执行
          ❌ 不支持
        

        

          MutationObserver
          ✅ 微任务
          ❌ 无 DOM
        

        

          微任务执行时机
          每个宏任务执行完后清空
          v11+ 每个阶段任务完成后清空（与浏览器一致）
        

        

          setTimeout(0) 最小延迟
          ~4ms（规范限制嵌套>5层）
          ~1ms
        

      


      
⚠️ Node.js v10 vs v11+ 的重要变化

      
// 在 Node.js v10 及之前：
setTimeout(() => {
  console.log('timer1');
  Promise.resolve().then(() => console.log('promise1'));
}, 0);

setTimeout(() => {
  console.log('timer2');
  Promise.resolve().then(() => console.log('promise2'));
}, 0);

// v10: timer1 → timer2 → promise1 → promise2（两个 timer 都执行完才清微任务）
// v11+: timer1 → promise1 → timer2 → promise2（每个 timer 后立即清微任务）


      

        🚨
        

          现代 Node.js（v11+）的行为已与浏览器对齐：每执行完一个宏任务，立即清空微任务队列，而不是等当前阶段所有任务执行完。
